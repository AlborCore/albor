# Internationalization

Albor treats translated text as a property of the *string*, not of the widget: a literal is
marked at the point it is written, extracted by the compiler, and resolved at runtime
against the locale's catalog.

## Marking strings

`@tr("literal")` marks a translatable string. It takes exactly one string literal:

```text
Label { text: @tr("Hello, ") + user_name + "!"; }
Button { text: @tr("Increment"); }
```

A key with holes — a sentence that interpolates — is written as concatenation of translated
pieces, exactly as above: each literal is its own key, and the dynamic part joins them. That
is what keeps a translation unit whole in every language, word order included.

The form compiles into a call through the translation layer; the literal it came from is
what the catalog is keyed by.

## Catalogs

A locale's catalog is keyed **by the source string** rather than by an identifier:

```cpp
albor::i18n::Catalog& catalog = albor::i18n::current();
catalog.add("Increment", "Aumentar");
const std::optional<std::string> found = catalog.find("Increment");
```

Keying by source has a deliberate property: a string that is never marked is never looked
up, a missing translation falls back to the source text, and there is no identifier table to
keep in step with the code.

## Direction

A catalog also knows how its locale reads:

```cpp
enum class TextDirection { LeftToRight, RightToLeft };
```

A right-to-left locale is what layout mirrors for — the same layout contract, rearranged.
Direction is a property of the locale, not of individual strings.

## The pipeline

1. `@tr` marks the literals in the `.ui` source.
2. The compiler extracts them; a generator fills a catalog table before startup.
3. At runtime a `@tr` resolves against `current()` — the catalog of the active locale.

The `i18n` module ships with the baseline described here: catalogs, locale lookup and the
direction enum. Per-locale formatting rules beyond this — plural forms, date and number
shapes — are not part of the language and belong to the application.

!!! note "Status"
    Text shaping (HarfBuzz through Skia) and the catalog layer are at baseline maturity.
    The cross-platform requirement that the same string measure identically on macOS,
    Windows and Linux is tracked as a product goal in the architecture specification.
